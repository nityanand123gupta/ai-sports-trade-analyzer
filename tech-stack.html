Technology Stack

Every tool used to build the AI Multi-Agent Sports Trade Analyzer, and why each one was chosen. Meant as a reference slide/handout when walking someone through the project.

Python 3 Jupyter Notebook Matplotlib CrewAI Gemini API (Google AI Studio) Anthropic Claude API python-dotenv Mermaid.js JSON Git / GitHub

Core language & runtime

ToolRole in this projectWhy this one
Python 3 All logic: data loading, the value-score model, the salary-cap rules engine, report generation. Readable, huge data/AI ecosystem, and the natural fit for Jupyter notebooks.
Jupyter Notebook The delivery format for the whole project — two notebooks instead of a script or web app. Lets you run one cell at a time and pause on the explanation above it — built for teaching, not just running.
Standard library:
json, dataclasses, enum, pathlib, copy		 json reads the data files; dataclasses/ enum model the trade-legality result and spending levels cleanly; copy.deepcopy safely duplicates data for the "what if" demo. No extra dependencies needed for straightforward data modeling.

Visualization

ToolRole in this projectWhy this one
Matplotlib The aging-curve line chart and the player/team value bar charts in notebook 1. The standard, dependency-light Python charting library — works inline in Jupyter with zero configuration.
Mermaid.js All architecture diagrams (in DESIGN.md/ DESIGN.pdf and the ones generated for teaching slides). Diagrams as text, version-controlled alongside the code, and rendered natively by GitHub — no separate diagramming tool needed.

The AI agent layer (notebook 2)

ToolRole in this projectWhy this one
CrewAI Defines the four AI agent personas (Data Scout, Analyst, Cap Specialist, General Manager) and runs them in sequence, each one able to see the previous agent's output. A lightweight, role-based framework purpose-built for exactly this "specialists collaborating in order" pattern — no need to hand-roll agent orchestration.
Google Gemini API
via Google AI Studio		 The default language model the AI agents reason with. Free API tier with no credit card required — removes the cost barrier to actually running the live agent demo.
Anthropic Claude API Alternative language model — used automatically if ANTHROPIC_API_KEY is set and no Gemini key is present. Keeps the project provider-agnostic; either key works without changing any code.
python-dotenv Loads API keys from a local .env file automatically. One less manual step (no export commands) and keeps secrets out of the notebook and out of git.

Data

ToolRole in this projectWhy this one
JSON data/sample_players.json (rosters, salaries, stats) and data/cap_rules.json (salary cap/tax/apron thresholds). Human-readable, trivial to load with the standard library, easy to edit by hand to try new trades.

Tooling & delivery

ToolRole in this projectWhy this one
Git / GitHub Version control and hosting for the whole project. Free, standard, and lets anyone clone and run the notebooks themselves.
nbconvert Executes the notebooks end-to-end (for testing/verification) and exports them to static HTML for sharing without needing Jupyter installed. Ships with Jupyter, no extra setup.
Headless Microsoft Edge Renders DESIGN.md (with its Mermaid diagrams) to DESIGN.pdf. Already installed on Windows — no separate PDF library needed; Chromium's print-to-PDF handles the JS-rendered diagrams correctly.
Why so little tooling? The deterministic engine (notebook 1) only needs the Python standard library plus Matplotlib. The point of the project is that the "AI" part is a thin, optional layer on top — so the core lesson doesn't depend on installing anything heavy.
